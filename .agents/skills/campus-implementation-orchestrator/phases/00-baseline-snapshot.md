# Phase 0 — Baseline Snapshot

## Objective
Capture the working state of the existing Luma clone before feature work.

## Implementation
- Run the existing application.
- Discover framework, language, package manager, routes, styling system, component architecture, auth, data layer, state management, build/test commands, and environment conventions.
- Run the existing build and available tests.
- Record existing routes and important reusable components.
- Record the existing event, calendar, navigation, authentication, form, modal, and responsive implementations.
- Create `.codex/campus-baseline/`.
- Record UI invariants based on the actual repository; do not invent them.
- If browser/screenshot tooling is available, capture representative baseline screens.

## Acceptance criteria
- Existing application starts successfully or any pre-existing failure is documented.
- Existing build/test status is recorded.
- Repository architecture is documented.
- UI invariants are documented.
- No product feature is implemented yet.
- No existing UI is redesigned.
